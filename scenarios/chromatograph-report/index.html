HPLC: une impureté hors limite dans le rapport d'injection

Objectif Lire les rapports d'injection qu'exporte un HPLC, unités collées et virgules décimales, et être prévenu quand une impureté dépasse sa spécification.

Le logiciel d'acquisition d'un HPLC exporte un rapport par injection: UTF-16, un bloc d'en-tête, puis les pics.

  • csv-file le lit ligne par ligne et porte l'échantillon sur chaque pic;
  • regex-extract sépare chaque valeur de son unité: 0,21% devient 0.21 et %;
  • une impureté au-delà de 0,15 %: une décision.

Un rapport par injection

Le logiciel d'acquisition exporte chaque injection dans un dossier.

  • UTF-16 avec un BOM (ff fe), CRLF
  • un bloc d'en-tête: Sample Name, Injection Date, Instrument, Method
  • les pics: 2,315min, 1 231,1mAU*s, 0,08%
  1. 1
    UTF-16

    Le hub le détecte au BOM: rien à déclarer.

L'échantillon sur chaque pic, l'unité à part

lines: true lit le rapport ligne par ligne. Un regex par type de ligne:

  • les lignes d'en-tête donnent sample, instrument, injected_at
  • une ligne de pic donne la valeur et son unité, en deux colonnes
  • fill-down, remis à zéro à chaque ligne Report: un rapport ne déborde jamais sur le suivant
  1. 1
    Pourquoi pas parse-number seul

    Il retire les symboles monétaires et les espaces, pas min ni %. Le regex coupe d'abord l'unité; parse-number lit ensuite la virgule décimale.

Ce que prouve cette étape

Un rapport fait pour l'impression devient une ligne par pic, typée.

manifests/10-injection-reports.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-chrom-a  connector_type: csv-file  scopes: [qc-hplc-a]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/chromatograph-report/a/*.csv   # the folder the acquisition software exports to  parser:    lines: true                    # a report, not a table: a header block, then the peaks  after_process: none  mapping:    cell:      - regex-extract: { column: line, pattern: "^([^;]+);", groups: { 1: field } }      # the header block: one key;value per line      - regex-extract: { column: line, pattern: "^Sample Name;(LOT \\S+)", groups: { 1: sample } }      - regex-extract: { column: line, pattern: "^Injection Date;(.+)$", groups: { 1: injected_at } }      - regex-extract: { column: line, pattern: "^Instrument;(.+)$", groups: { 1: instrument } }      - regex-extract: { column: line, pattern: "^Method;(.+)$", groups: { 1: method } }      # a peak: the value and its glued unit, cut apart      - regex-extract:          column: line          pattern: "^(\\d+);([\\d ,]+)(min);([^;]+);([\\d ,]+)(mAU\\*s);([\\d ,]+)(%)$"          groups: { 1: peak, 2: rt, 3: rt_unit, 4: peak_name, 5: area, 6: area_unit, 7: amount_pct, 8: amount_unit }      # the report's header, on each of its peaks; a new report starts empty      - fill-down: { columns: [sample, injected_at, instrument, method], reset-when: { column: field, in: [Report] } }      - parse-number: { column: rt, decimal-separator: "," }      - parse-number: { column: area, decimal-separator: "," }      - parse-number: { column: amount_pct, decimal-separator: "," }      - parse-date: { column: injected_at, formats: ["dd/MM/yyyy HH:mm:ss"] }

La limite de la spécification

Le Process écoute la table des rapports.

  • peak_name~Impurity: les pics d'impureté
  • amount_pct>0.15: au-delà de la limite, pas dessus
  • key: sample, la décision porte le lot
  1. 1
    Appliqué après le premier dépôt

    Un Process ne juge que les lignes nouvelles. Les six premiers rapports sont conformes.

Ce que prouve cette étape

Une limite de spécification se déclare sur les colonnes lues dans l'instrument.

manifests/20-impurity-over-limit.yaml
apiVersion: apps.lumnik.io/v1kind: Processmetadata:  name: scenario-chrom-impurity-aspec:  scope: qc-hplc-a  on: { event: data.row.changed, table: connector.t_scenario_chrom_a }  when:    - peak_name~Impurity    - amount_pct>0.15                # the specification's limit for a specified impurity  emit:    type: decision.impurity-over-limit-a    message: "{sample}: {peak_name} at {amount_pct} % (limit 0.15 %), {instrument}, injected {injected_at}"    key: sample

Limites

  • La table garde chaque ligne du rapport, en-tête compris: une règle lit les pics par leurs colonnes.
  • Une limite pour toutes les impuretés: une limite par impureté, c'est un Process par impureté.
  • Le regex attend ces trois unités; une autre unité laisse la ligne non découpée, et la règle ne la voit pas.
  • Lots, pics et teneurs synthétiques.

Laboratoire · HPLC

Les résultats dorment dans les rapports de l'instrument.

Un fichier par injection, fait pour être imprimé.

UTF-16, 1 532 117,2mAU*s, 0,21%

Le problème

LOT 26-0459: impureté B à 0,21 %.

  • La limite est 0,15 %.
  • Le rapport se lit à l'œil, quand il est lu.

Ce qui n'est pas modifié

Le logiciel d'acquisition reste tel quel.

  • Son propre export, dans son propre dossier.
  • Aucun script, aucune conversion à la main.

Ce qu'il a fallu écrire

pattern: "([\\d ,]+)(%)"
fill-down: { reset-when: Report }

Un regex par type de ligne, un fill-down.

  • L'unité dans sa propre colonne.
  • Un Process: impureté au-delà de 0,15 %.

Le résultat

Une décision, LOT 26-0459.

  • LOT 26-0461 est pile à 0,15 %: pas au-delà.
  • 36 pics, 0 erreur de cellule.
