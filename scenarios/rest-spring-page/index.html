Un Page de Spring: quand Spring change son JSON, une ligne suit.

Objectif Lire tout le catalogue d'une app Spring Boot, page après page, avant et après que l'équipe change la sérialisation de ses Page.

Un contrôleur Spring renvoie le Page du repository. lumnik le lit avec un preset:

  • pagination: { kind: spring-page }: 130 articles en 3 requêtes;
  • l'équipe suit l'avertissement de Spring et passe en VIA_DTO: le total passe sous page, le même manifeste lit tout, avec une page vide de trop;
  • une ligne, spring-paged-model: de nouveau 3 requêtes.

Un contrôleur Spring, 130 articles

Spring Boot 3.4.5, Spring Data JPA. Le contrôleur renvoie le Page du repository tel quel.

  • content: 50 articles par page
  • totalPages: 3
  • totalElements: 130
  1. 1
    L'avertissement de Spring

    Spring écrit dans son journal que cette forme n'est pas garantie stable, et conseille VIA_DTO.

Ce que prouve cette étape

La réponse dit combien de pages il y a.

Une ligne: pagination: { kind: spring-page }

Un connecteur rest-generic.

  • pagination: spring-page: page et size, de 0 jusqu'à totalPages
  • clé: la référence de l'article
  1. 1
    3 requêtes

    page=0, 1, 2, lues dans le journal d'accès de Tomcat.

Ce que prouve cette étape

Catalogue · articles

Le catalogue est dans une app Spring Boot.

Il faut lire tous les articles, chaque nuit.

Spring Boot 3.4, une app de lab

Le problème

L'app rend ses articles par pages.

  • Chaque page dit combien il y en a.
  • Un jour, l'équipe change la forme de cette réponse.

Ce qui n'est pas modifié

Le code de l'app reste le sien.

  • Le contrôleur renvoie le Page de Spring.
  • Le choix de sérialisation est celui de l'équipe.

Ce qu'il a fallu écrire

pagination: { kind: spring-page }

On nomme le framework.

Un connecteur de 23 lignes: 130 articles, 3 requêtes.

Le changement

L'équipe suit l'avertissement de Spring.

  • Le total passe sous page.
  • Le hub lit tout, avec une page vide de trop.

La correction

pagination: { kind: spring-paged-model }

Une ligne change.

  • De nouveau 3 requêtes.
  • 130 articles, une ligne chacun.

La limite

Une app de lab, pas un produit publié.

  • Écrite avec les classes de Spring.
  • Sans le bon preset, rien n'est perdu: une requête de trop.
