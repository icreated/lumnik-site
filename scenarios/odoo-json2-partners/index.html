Odoo 19 et son API JSON-2: la page se lit dans le corps

Objectif Lire les 250 contacts d'un vrai Odoo 19 par son API JSON-2, page par page, sans base de données ouverte.

Odoo 19 remplace XML-RPC et JSON-RPC, retirés en Odoo 22, par POST /json/2/<modèle>/<méthode>. Chaque intégration existante doit migrer, et Odoo Online n'ouvre pas sa base: l'API est sa seule porte. JSON-2 lit offset et limit dans le corps JSON seulement.

  • body: le domaine, les champs et l'ordre qu'Odoo attend
  • param_binding: body écrit offset et limit dans le corps
  • trois requêtes, 250 contacts, aucun en double

250 contacts en trois pages

Un vrai Odoo 19 tourne en Docker. Une clé d'API ouvre JSON-2. 250 contacts sont créés par JSON-2 lui-même.

  • body: le domaine ref =like LUM-%, les champs, l'ordre
  • param_binding: body, offset et limit vont dans le corps
  • X-Odoo-Database: la base visée
  • la dernière page, courte, arrête la lecture

Ce que prouve cette étape

La page va là où l'API la lit.

manifests/10-partners.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-odoo-json2-a  connector_type: rest-generic  scopes: [crm-a]spec:  base_url: http://host.docker.internal:18072  auth:    kind: bearer    token_env: SCENARIO_ODOO_JSON2_A_KEY   # an Odoo API key, Preferences → Account Security  headers:    - { name: X-Odoo-Database, value: scen }  endpoints:    - id: partners      method: POST      path: /json/2/res.partner/search_read      body:                                # sent as JSON: JSON-2 reads its arguments from the body        domain: [[ref, "=like", "LUM-%"]]        fields: [name, ref, city, email]        order: id      pagination:        kind: offset        param_binding: body                # offset and limit written into the body, page after page        offset_param: offset        limit_param: limit        limit: 100        response_path: $      target:        kind: hybrid        table: connector.scenario_odoo_partners_a        unique_key: $.id        promote:          - { name: partner_id, path: $.id, type: bigint }          - { name: name, path: $.name, type: text }          - { name: ref, path: $.ref, type: text }          - { name: city, path: $.city, type: text }          - { name: email, path: $.email, type: text }

Limites

  • La clé d'API est créée par le shell d'Odoo: un utilisateur la crée dans Préférences, Sécurité du compte.
  • Pas encore de watermark: chaque run relit le domaine entier.
  • Odoo 18 et avant n'ont pas JSON-2: lisez leur PostgreSQL (odoo-product-name-json).
  • Sans icreated/lumnik#2123, offset et limit partaient dans l'URL, qu'Odoo ignore: chaque page renvoyait tout.
  • 250 contacts synthétiques.
