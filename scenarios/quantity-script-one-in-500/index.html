Une valeur imprévue sur 500 : la ligne en lettre morte, les 499 autres écrites.

Un bon de réception saisi à la main : 500 lignes, des quantités écrites « 12,5 kg » ou « 3 pce ». Un script Kotlin de l'opérateur les lit en nombre et en unité. La ligne 317 dit « env. 4 kg ». Que deviennent les 499 autres ?

L'opérateur dépose sa lecture des quantités

La version 1 du script coupe la quantité en un nombre et une unité. Elle ne prévoit que « 12,5 kg » et « 3 pce ». lm hook scripts montre son empreinte.

  1. 1
    Deux formes

    Aucune autre n'est prévue.

Ce que prouve cette étape

Le script est celui de l'opérateur ; le manifeste ne fait que le nommer.

Un script qui lève une exception arrête le run

Sur « env. 4 kg », le script lève une exception : le run échoue et n'écrit aucune des 500 lignes. Le message nomme le script, le type d'exception et la ligne du script, jamais la valeur lue.

  1. 1
    line 5

    La ligne du script, pas celle du fichier.

L'opérateur déclare illisible ce qu'il ne sait pas lire

La version 2 lit les deux formes connues ; pour toute autre, elle appelle unreadable au lieu de deviner. Le hub compte alors la cellule, comme pour un transformer intégré.

  1. 1
    unreadable

    Compté, jamais deviné.

Ce que prouve cette étape

Un script peut dire « je ne sais pas lire cette valeur » sans arrêter le run.

manifests/quantity-v2.kts
// Operator-provided: reads a quantity written "12,5 kg" or "3 pce" into a number and a unit.// A quantity in any other shape is declared unreadable: counted, never guessed.@Suppress("UNCHECKED_CAST")val cells = bindings["cells"] as MutableMap<String, Any?>val m = Regex("(\\d+(?:,\\d+)?) (kg|pce)").matchEntire((cells["quantity"] as String).trim())if (m == null) {    (bindings["unreadable"] as Runnable).run()} else {    cells["qty"] = m.groupValues[1].replace(',', '.')    cells["unit"] = m.groupValues[2]}

Les 499 lignes lisibles sont écrites

L'intégrateur ajoute on-error: default: dlq. Les 500 lignes sont relues : 499 écrites avec leur quantité et leur unité, une écartée et comptée. L0316 et L0318 sont dans la table.

  1. 1
    default

    Le hook kotlin n'a pas de colonne : default décide.

Limites

  • Le message d'un script qui échoue donne la ligne du script, pas celle du fichier : il faut un script qui déclare la valeur illisible pour savoir quelle ligne pose problème.
  • La lettre morte nomme le hook kotlin, pas la colonne : un script peut écrire plusieurs cellules.
  • Lignes synthétiques.
