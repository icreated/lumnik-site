Le code-barres faux repéré à l'import : un script Kotlin fourni par l'opérateur, nommé par le manifeste.

Un export catalogue porte des codes EAN-13, dont certains faux. Aucun transformateur intégré ne calcule une clé de contrôle. L'opérateur du hub dépose un script Kotlin dans le répertoire de scripts du hub ; le manifeste le nomme, sans transporter de code. Un brouillon qui ne compile pas est refusé dès la validation, avec sa ligne et sa colonne.

// Operator-provided: checks an EAN-13 bar code and says why one is wrong.@Suppress("UNCHECKED_CAST")val cells = bindings["cells"] as MutableMap<String, Any?>val ean = (cells["ean"] as? String)?.trim().orEmpty()cells["ean_status"] = if (!Regex("\\d{13}").matches(ean)) {    "malformed"} else {    val sum = ean.take(12).mapIndexed { i, c -> (c - '0') * (if (i % 2 == 0) 1 else 3) }.sum()    if ((10 - sum % 10) % 10 == ean[12] - '0') "valid" else "wrong-check-digit"}

L'opérateur dépose deux scripts, l'intégrateur les voit

Un brouillon et le contrôle terminé sont copiés dans le répertoire de scripts du hub, monté en lecture seule. lm hook scripts les liste avec leur taille et leur empreinte SHA-256 : l'intégrateur sait quelle version le hub détient.

  1. 1
    Lecture seule

    Le hub ne peut pas écrire un script.

  2. 2
    SHA-256

    L'empreinte de chaque version.

Chaque code-barres contrôlé à l'import

Le manifeste nomme le script terminé. Le run lit les 10 produits ; le script calcule la clé de chaque EAN-13 et écrit son verdict dans une colonne ean_status. Deux clés fausses et un code de 12 chiffres ressortent.

  3. 3
    1 mal formé

    12 chiffres au lieu de 13.

Ce que prouve cette étape

Une règle métier absente des transformateurs s'ajoute sans toucher au hub.

Limites

  • Un script s'exécute avec tous les droits du hub : seul l'opérateur peut en installer un.
  • Un script remplacé s'applique au lot suivant, pas au milieu d'un lot.
  • Le script tourne sur les imports CSV.
  • Catalogue synthétique, codes au préfixe 200 réservé à l'usage interne.
