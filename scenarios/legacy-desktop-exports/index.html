Un parc de machines réparti dans trois bases legacy

Objectif Réunir en un seul parc les exports OpenEdge, FoxPro et Access de trois ateliers, chacun lu dans son format et son encodage, et voir la seule machine où deux registres divergent.

Un groupe industriel a trois ateliers, et chaque atelier tient son parc de machines dans sa propre base de bureau, installée il y a vingt ou trente ans.

  • Nord exporte depuis Progress OpenEdge, Est depuis FoxPro pour DOS, Sud depuis Access;
  • chaque format demande son geste: ? pour inconnu, -1 pour oui, une heure de minuit, une année sur deux chiffres;
  • l'export FoxPro, lu sans sa page de code, est deviné en windows-1252: le run le dit et s'arrête sur le É de « Électroérosion »;
  • réunis, les trois registres font 17 machines et un litige: la rectifieuse passée d'Est à Sud.

Trois registres, trois exports

Chaque atelier exporte son registre comme sa base sait le faire.

  • Nord, Progress OpenEdge, l'instruction EXPORT: séparateur espace, ISO-8859-1
  • Est, FoxPro 2.6 pour DOS, COPY TO … DELIMITED: virgule, page de code 850
  • Sud, Access, l'assistant d'export texte: point-virgule, une ligne d'en-tête, windows-1252
  1. 1
    Le mémo FoxPro ne sort pas

    COPY TO laisse les champs mémo de côté: les notes d'Est restent dans FoxPro. Aucun réglage du hub ne les fait apparaître.

OpenEdge: ? pour inconnu, l'année sur deux chiffres

Le connecteur csv-file, séparateur espace, les chaînes entre guillemets.

  • regex-replace: ? est la valeur inconnue d'OpenEdge, elle devient vide avant d'être typée
  • parse-date MM/dd/yy, century-from: 1950: 09/17/79 est 1979, pas 2079
  • yes/no est un booléen, les notes sur deux lignes restent entières
  1. 1
    Sans le regex-replace

    parse-date ne lit pas ?: la cellule est vidée quand même, mais comptée en erreur. M-1104, reçue sans carnet, n'a ni révision ni contrat connus.

FoxPro sans sa page de code: le run le dit

Le connecteur ne déclare pas d'encodage. Le hub devine windows-1252, avec 26 % de confiance.

  • les quatre premières lignes sont lues, accents faux: Hur‚, Perceuse … colonne
  • la cinquième porte É, l'octet 0x90, que windows-1252 ne définit pas: le fichier s'arrête là
  • le run finit Partial; sa note et la lettre morte nomment l'encodage, l'octet et la ligne
  1. 1
    Deux signaux

    La note dit que l'encodage était deviné (#1885). La lettre morte dit quel octet n'a pas de caractère, et à quelle ligne (#1887).

Access: -1 pour oui, minuit, la virgule

L'assistant d'export texte d'Access écrit à sa façon.

  • une date s'écrit 14/03/2019 00:00:00: le format avec ' 00:00:00' en littéral donne une date, pas minuit UTC
  • Oui/Non s'écrit -1/0: parse-boolean le déclare
  • 47000,00 est un nombre, le mémo garde ses deux lignes
  1. 1
    Les noms de colonnes

    Libellé, Révision: l'en-tête d'Access donne ses noms accentués, que l'entité reprend tels quels.

Limites

  • Les mémos coupés à la source ne se voient pas: Access coupe un mémo à 255 caractères à l'export (M-3303), FoxPro COPY TO n'exporte pas les mémos. Le hub lit ce qu'il reçoit.
  • Une page de code devinée reste une supposition: le hub signale un fichier qui ressemble à une page DOS lue en windows-1252, pas toutes les erreurs d'encodage.
  • Après un mauvais encodage, le fichier se relit avec lm endpoint reset-cursor; le connecteur ne le relit pas de lui-même.
  • Le hub n'a pas de dialecte jdbc-generic pour OpenEdge, FoxPro ou Access: seuls leurs exports sont lus.
  • La table de lm entity get se décale sur un mémo de plusieurs lignes (#1889); la page montre le parc par SQL.
  • Machines, dates et valeurs synthétiques; les formats d'export sont reproduits, pas produits par les logiciels eux-mêmes.

Maintenance · trois ateliers

Trois ateliers, trois bases legacy.

OpenEdge à Nord, FoxPro pour DOS à Est, Access à Sud. Aucune ne sera migrée.

machines.d · MACHINES.TXT · Machines.txt

Le problème

FoxPro écrit en CP850. Le hub devinait windows-1252.

  • Huré devenait Hur‚, sans un mot.
  • Le É de « Électroérosion » arrêtait le fichier à la ligne 0.

Ce qui n'est pas modifié

Les trois bases restent telles quelles.

  • Leurs exports sont ceux qu'elles savent faire.
  • Aucun fichier retouché, aucun pilote ODBC.

Ce qu'il a fallu écrire

encoding: IBM850

Une ligne dans le connecteur FoxPro.

  • Puis lm endpoint reset-cursor.
  • Les six machines d'Est, accents justes.

Ce qui a été corrigé

Un encodage deviné est dit (#1885).

  • Un octet sans caractère est nommé, avec sa ligne (#1887).
  • 17 machines, un litige: M-2206.
