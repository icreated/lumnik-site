HL7 v2: un résultat au-dessus de sa norme que l'analyseur ne signale pas

Objectif Lire les résultats HL7 v2 de deux analyseurs, et être prévenu quand une valeur dépasse la norme envoyée avec elle, même sans drapeau d'anomalie.

Deux analyseurs de chimie, HL7 v2.5.1 ORU^R01: des segments terminés par un retour chariot seul.

  • csv-file lit un segment par ligne, MSH, PID, OBR, OBX;
  • l'échantillon descend sur chaque résultat;
  • un Process compare la valeur à la norme envoyée à côté, quel que soit le drapeau.

Deux analyseurs, huit messages par lot

Chaque échantillon est un message. Chaque segment se termine par un retour chariot seul, \r.

  • MSH: l'analyseur et l'identifiant du message
  • PID: l'échantillon et son lot
  • OBX: un résultat, son unité, sa norme, son drapeau
  1. 1
    Un firmware ancien

    CHEM-02 laisse vide OBX-8, le drapeau d'anomalie.

Un segment par ligne, l'échantillon sur chaque résultat

lines: true lit un segment par ligne: le \r seul en termine un. Un regex par type de segment découpe ses champs.

  • fill-down porte l'analyseur et l'échantillon sur les lignes OBX
  • reset-when: MSH, un nouveau message repart vide
  • parse-number, parse-date
  1. 1
    Chaque segment reste

    MSH, PID et OBR sont aussi des lignes: un filtre passe avant fill-down, jamais après. La règle lit segment=OBX.

Ce que prouve cette étape

Un message HL7 devient des lignes qu'une règle sait lire, sans moteur d'interface.

manifests/10-analyser-results.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-hl7-a  connector_type: csv-file  scopes: [qc-chem-a]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/hl7-analyser-results/a/*.hl7   # the folder the analysers drop their batches in  parser:    lines: true                    # one segment per row; HL7's lone carriage return ends a segment  after_process: none  mapping:    cell:      - regex-extract: { column: line, pattern: "^([A-Z][A-Z0-9]{2})\\|", groups: { 1: segment } }      # MSH: the analyser (MSH-3) and the message's control id (MSH-10)      - regex-extract: { column: line, pattern: "^MSH\\|[^|]*\\|([^|]*)\\|(?:[^|]*\\|){6}([^|]*)\\|", groups: { 1: analyser, 2: message_id } }      # PID: the sample (PID-3, first component) and the lot (PID-5)      - regex-extract: { column: line, pattern: "^PID\\|[^|]*\\|\\|([^^|]*)[^|]*\\|\\|([^|]*)", groups: { 1: sample, 2: lot } }      # OBX: the test, the value, the unit, the reference range, the flag, the time of observation      - regex-extract:          column: line          pattern: "^OBX\\|(\\d+)\\|NM\\|([^^|]*)\\^([^|]*)\\|\\|([^|]*)\\|([^|]*)\\|([^-|]*)-([^|]*)\\|([^|]*)\\|(?:[^|]*\\|){5}(\\d{14})"          groups: { 1: obx_seq, 2: test_code, 3: test_name, 4: value, 5: unit, 6: range_low, 7: range_high, 8: flag, 9: observed_at }      # the message's analyser and sample, on every segment of the message      - fill-down: { columns: [analyser, message_id, sample, lot], reset-when: { column: segment, in: [MSH] } }      - parse-number: { column: value }      - parse-number: { column: range_low }      - parse-number: { column: range_high }      - parse-date: { column: observed_at, formats: ["yyyyMMddHHmmss"] }

La norme, pas le drapeau

Le Process compare chaque résultat à la norme que l'analyseur a envoyée à côté.

  • segment=OBX: les résultats seulement
  • "value>{range_high}": deux colonnes de la ligne
  • key: sample, la décision porte l'échantillon
  1. 1
    Appliqué après le premier lot

    Un Process ne juge que les lignes nouvelles. Le premier lot est entièrement dans la norme.

Ce que prouve cette étape

Une règle tient même quand le drapeau de l'analyseur manque.

manifests/20-above-range.yaml
apiVersion: apps.lumnik.io/v1kind: Processmetadata:  name: scenario-hl7-above-range-aspec:  scope: qc-chem-a  on: { event: data.row.changed, table: connector.t_scenario_hl7_a }  when:    - segment=OBX    - "value>{range_high}"           # above the range the analyser sent with the result, whatever its flag  emit:    type: decision.above-range-a    message: "{sample} ({lot}) {test_name}: {value} {unit}, above {range_low}-{range_high} on {analyser}, flag '{flag}'"    key: sample

Limites

  • La table garde chaque segment: une View ou une règle lit segment=OBX. Aucun hook ne retire une ligne après fill-down.
  • Les conditions se combinent en ET: sous la norme, c'est un second Process.
  • Seuls les résultats NM sont lus; un OBX texte (ST) ou codé (CE) garde sa ligne sans colonnes.
  • Des fichiers, pas MLLP: les analyseurs écrivent dans un dossier, le hub n'écoute pas de socket.
  • Échantillons, lots et résultats synthétiques.

Laboratoire · HL7 v2

Les analyseurs parlent HL7 v2.

Un message par échantillon, un segment par ligne.

ORU^R01, MSH · PID · OBR · OBX

Le problème

Un analyseur n'envoie aucun drapeau.

  • Sa créatinine à 162 µmol/L passe inaperçue.
  • La norme était pourtant dans le message.

Ce qui n'est pas modifié

Les analyseurs restent tels quels.

  • Leurs fichiers HL7, dans leur dossier.
  • Aucun moteur d'interface, aucun code.

Ce qu'il a fallu écrire

fill-down: { columns: [sample], reset-when: MSH }
when: [segment=OBX, "value>{range_high}"]

Un regex par segment, une condition.

  • csv-file: les segments en lignes.
  • Un Process: la norme, pas le drapeau.

Le résultat

Deux décisions, dont une sans drapeau.

  • Lactate 3,1, signalé H.
  • Créatinine 162, drapeau vide.
