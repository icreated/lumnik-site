Sequelize: le service annonce 260 commandes pour 130

Objectif Lire toutes les commandes d'un service Node par son API, sans croire un total faux.

Un service Express et Sequelize, 130 commandes et leurs lignes, lues par offset et limit.

  • au calme: les 130, le count de chaque page vérifié;
  • avec les lignes, sans distinct: le count dit 260, le run refuse;
  • avec distinct: true: 130 sur 130;
  • une commande supprimée pendant la lecture: la liste est relue.

Les 130 commandes en une ligne

Le service de l'équipe: Express, findAndCountAll, 130 commandes fictives et leurs lignes. Trois routes, trois count pour deux lignes demandées.

  • kind: sequelize: offset et limit, lit rows, vérifie count
  • limit: 50 par page, 3 pages
  1. 1
    Un témoin

    Si le hub lit moins de lignes que le count, le run échoue au lieu de se dire complet.

Ce que prouve cette étape

Une ligne suffit pour lire une API Sequelize.

Le count dit 260: le run refuse

La même lecture sur la route qui inclut les lignes. Sans distinct: true, Sequelize compte les lignes jointes, pas les commandes. Le hub lit 130 commandes et refuse de se dire complet.

  • count: 260
  • lues: 130
  1. 1
    Ce que lumnik ne sait pas

    Un total faux et des lignes manquantes se ressemblent. Il refuse les deux.

Ce que prouve cette étape

Un total faux ne passe pas pour une lecture complète.

Une commande supprimée: la liste est relue

Dix par page, une par seconde. On supprime CMD-0001, déjà lue en page 1. Les commandes suivantes remontent d'une place, le count passe à 129, le hub relit la liste.

  • default_rate_limit: une page par seconde
  • IN 189: la première lecture, puis les 129
  1. 1
    Rien de perdu

    Les 129 commandes restantes sont toutes dans la table.

Limites

  • lumnik ne distingue pas un total faux de lignes manquantes: il refuse les deux. La correction est dans le service.
  • Une commande supprimée reste dans la table du hub: une lecture complète ajoute et met à jour, elle n'efface pas.
  • 130 commandes fictives, créées au démarrage du service.

Ventes · commandes

Les commandes sont dans un service Node.

Il faut toutes les lire, avec leurs lignes.

Express, Sequelize 6.37, 130 commandes

Le problème

L'API rend la liste par pages.

  • offset et limit, 50 par page.
  • Chaque page donne un count.

Ce qui n'est pas modifié

Le service reste tel quel.

  • Son API, en lecture.
  • Aucun module, aucun réglage.

Le piège

Le count compte les lignes jointes.

  • include sans distinct: true.
  • 260 annoncées pour 130 commandes.

Ce qu'il a fallu écrire

pagination: { kind: sequelize }

Une ligne.

  • Le count de chaque page est vérifié.
  • Un connecteur de 21 lignes.

Quand le total est faux

Le run échoue, il ne ment pas.

  • 260 annoncées, 130 lues.
  • Le message donne les deux chiffres.

La correction

Elle est dans le service.

  • distinct: true dans findAndCountAll.
  • 130 sur 130, relu si la liste bouge.
