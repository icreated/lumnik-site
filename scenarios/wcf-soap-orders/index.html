SOAP WCF et WS-Security: le mot de passe a tourné, le Fault le dit

Objectif Lire un service WCF protégé par un UsernameToken, survivre à la rotation de son mot de passe, et être prévenu d'une commande confirmée après sa date promise.

Un distributeur expose ses commandes ouvertes par un service WCF: HTTPS sous la CA de l'entreprise, un UsernameToken dans l'enveloppe.

  • la CA et le mot de passe vivent dans lm secret, jamais dans le manifeste;
  • le mot de passe tourne: en HTTP/2 le Fault se perd, en HTTP/1.1 il nomme la cause;
  • trois commandes confirmées après leur date promise, trois décisions.

Un service de commandes WCF, sous la CA de l'entreprise

BasicHttpBinding en TransportWithMessageCredential, identifiant UserName: le service exige un UsernameToken WS-Security dans l'enveloppe.

  • HTTPS signé par la CA interne de l'entreprise
  • GetOpenOrders(page, pageSize), le drapeau IsLastPage
  • la CA et le mot de passe vont dans lm secret
  1. 1
    CoreWCF

    Le portage de WCF sur .NET 8. Binding et valeurs par défaut sont ceux de WCF; le service tourne sous Kestrel, pas sous IIS.

30 commandes ouvertes, trois pages

Le connecteur rest-generic, forme soap.

  • tls.ca_secret: cette CA seule est crue, pour ce connecteur
  • header: le UsernameToken, le mot de passe par {{secret:…}}
  • body: {{page}} et {{page_size}}, IsLastPage arrête la boucle
  1. 1
    Sans Timestamp

    CoreWCF accepte un UsernameToken sans wsu:Timestamp. Il refuse un Timestamp périmé: un horodatage figé dans le manifeste serait refusé dès le lendemain.

Ce que prouve cette étape

Un service WCF sécurisé dans l'enveloppe se lit sans proxy ni code .NET.

Confirmée après la date promise au client

Le Process écoute la table ext.* du connecteur.

  • confirmed_date>{promised_date}: deux colonnes de la même ligne
  • key: order_no, la décision porte le numéro de commande
  1. 1
    Avant l'appel du client

    La décision arrive le matin où l'entrepôt confirme, pas le jour où la commande manque.

Ce que prouve cette étape

Une règle compare deux dates du même document, sans date écrite en dur.

Le mot de passe a tourné: I/O error, six requêtes

Le lendemain matin, l'informatique fait tourner le mot de passe du compte. Le secret garde l'ancien.

  • le service répond 500 et son Fault, puis coupe le flux HTTP/2
  • le hub négocie HTTP/2: la coupure efface la réponse déjà reçue
  • pré-requête et run: I/O error, chaque appel réessayé
  1. 1
    Le journal du service

    Six POST en HTTP/2, six 500, pour une pré-requête et un run: le refus d'identifiants est réessayé comme une panne réseau.

En HTTP/1.1, le Fault nomme la cause

Une ligne dans le connecteur: http_version: "1.1".

  • le run échoue avec le faultstring du service
  • un Fault n'est pas réessayé: deux requêtes, une par porte
  • la pré-requête ne dit encore que HTTP 500 (#1861)
  1. 1
    Entre guillemets

    1.1 sans guillemets est un nombre pour YAML: lm validate le refuse.

Limites

  • Joué contre CoreWCF sous Kestrel. Un WCF .NET Framework sous IIS n'a pas été joué: sa tolérance à un UsernameToken sans Timestamp n'est pas vérifiée ici.
  • Le mot de passe part en clair dans l'enveloppe (PasswordText), protégé par HTTPS. Un PasswordDigest demande un nonce et une date à chaque appel: aucun placeholder ne les fabrique.
  • La pré-requête lit HTTP 500 là où le run nomme le Fault (#1861).
  • SOAP 1.1 seulement: un service en SOAP 1.2 (wsHttpBinding) n'est pas lu.
  • Commandes, clients et mots de passe synthétiques.

Ventes · WCF

Les commandes vivent derrière un service WCF.

SOAP, HTTPS, un UsernameToken dans l'enveloppe.

<wsse:UsernameToken>

Le problème

Le mot de passe a tourné. Le hub disait: I/O error.

  • Le service avait répondu son Fault, puis coupé le flux HTTP/2.
  • Trois tentatives pour un refus d'identifiants.

Ce qui n'est pas modifié

Le service reste tel quel.

  • Son binding, sa CA, son contrat.
  • Aucun proxy, aucun code .NET.

Ce qu'il a fallu écrire

http_version: "1.1"

Une ligne dans le connecteur.

  • Le Fault arrive entier.
  • Il n'est pas réessayé.

Ce qui a été corrigé

La version HTTP se choisit par connecteur (#1859).

  • Nouveau secret, même manifeste: la lecture reprend.
  • Trois commandes en retard: trois décisions.
