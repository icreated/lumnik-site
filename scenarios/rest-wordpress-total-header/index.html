WordPress annonce 46 articles et en sert 31: le run échoue au lieu de passer vert.

Objectif Lire tous les articles d'un site WordPress, et refuser une lecture partielle quand un plugin en cache sans changer le compte.

L'API REST de WordPress pagine par l'en-tête Link et publie son compte dans X-WP-Total. lumnik suit l'un et vérifie l'autre:

  • 46 articles annoncés, 46 lus: le run passe;
  • un plugin « réservé aux membres » cache 15 articles, le compte reste 46: le run échoue et donne les deux chiffres;
  • lu en tant que membre, avec un mot de passe d'application, les 46 articles reviennent.

Un vrai WordPress: 46 articles, le compte en en-tête

WordPress 6.6 et MariaDB. 45 articles dans 3 catégories, plus l'article d'installation. L'API REST répond:

  • Link: la page suivante
  • X-WP-Total: le nombre d'articles
  • X-WP-TotalPages: le nombre de pages

Un mu-plugin du lab joue un plugin « réservé aux membres », éteint au départ.

  1. 1
    Le plugin

    Il retire les articles de la catégorie Atelier après la requête (filtre the_posts), comme le font ces plugins: WordPress les a déjà comptés.

46 annoncés, 46 lus

Un connecteur rest-generic, sans authentification.

  • pagination: link-header: suit rel="next", 5 pages de 10
  • response_path: $: le corps est la liste
  • total_header: X-WP-Total: le compte de WordPress, comparé au compte lu

Lu en tant que membre: 46 sur 46

Le connecteur lit avec le compte abonné lumnik-reader et son mot de passe d'application.

  • auth: basic: l'identifiant et le mot de passe d'application, rangé par lm secret
  1. 1
    http

    WordPress n'accepte un mot de passe d'application sans https que sur un site déclaré local, comme celui du lab.

Limites

  • Le témoin vaut ce que vaut le compte: un plugin qui corrigerait aussi X-WP-Total cacherait ses articles sans que rien ne se voie.
  • Le hub lit ce que son compte voit: un article réservé à un autre rôle n'est pas lu.
  • Sur un vrai site, le mot de passe d'application passe par https.
  • Site WordPress de démonstration, articles synthétiques; le plugin « réservé aux membres » est un mu-plugin du lab.

Le problème

Le compte ne bouge pas.

  • Le plugin retire les articles après la requête.
  • WordPress annonce toujours 46.

Ce qui n'est pas modifié

  • Un compte abonné et son mot de passe d'application.
