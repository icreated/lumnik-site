L'export qui ment : une ligne illisible ne passe pas en silence.

Un ERP exporte chaque nuit son catalogue d'articles en un seul fichier. Un libellé contient le séparateur, sans guillemets. lumnik met la ligne de côté avec ses valeurs brutes, ne retire rien du catalogue tant qu'elle est illisible, et ne ferme la lettre morte que sur le run qui l'a vraiment relue.

A04 part en quarantaine, les neuf autres sont écrits

Le libellé de A04 contient un « ; » que l'export ne met pas entre guillemets : quatre valeurs pour trois colonnes. La ligne va dans les lettres mortes avec ses valeurs brutes, le fichier et le numéro de ligne.

  1. 1
    Rien de retouché

    La valeur en trop n'est jamais coupée pour faire tenir la ligne.

  2. 2
    Le run continue

    IN 10, OUT 9, une lettre morte.

Ce que prouve cette étape

A09 quitte le catalogue, A04 toujours illisible : Failed

Le fichier est toute la table : A09 absent devrait être retiré. Mais une ligne du fichier est en lettre morte ; le run échoue et ne retire rien.

  1. 1
    A09 attend

    Sa dernière version reste tant qu'une ligne du fichier est illisible.

  2. 2
    Deux lettres

    Chaque nuit qui lit la ligne en ajoute une.

Ce que prouve cette étape

Un retrait ne passe pas tant que le fichier n'a pas été lu en entier.

A04 écrit, A09 retiré

L'export met le libellé entre guillemets. Le run lit les neuf lignes, retire A09 et termine Completed. Les deux lettres mortes restent ouvertes : le hub ne relit jamais une lettre morte.

  1. 1
    Retrait

    1 ligne retirée, la source ne la contient plus.

  2. 2
    Lettres ouvertes

    Les fermer est un geste de l'intégrateur.

Ce que prouve cette étape

La nuit corrigée rattrape la table sans geste manuel sur les données.

Fermer sur la nuit 2 : refusé

La nuit 2 a remis A04 en quarantaine. La donner comme preuve du rejeu est refusé, en nommant la raison.

  1. 1
    Le run prouve

    Completed, même connecteur, démarré après la lettre.

  2. 2
    Sinon

    discard ferme une lettre qu'aucun run n'a portée.

Les deux lettres fermées par le run qui a écrit A04

lm dlq replayed --new-run-id avec la nuit 3. lm dlq get dit par quel run et quand.

  1. 1
    Une seule fois

    Une lettre fermée refuse une seconde fermeture.

  2. 2
    Traçable

    Le run et l'heure restent sur la lettre.

Ce que prouve cette étape

Chaque lettre fermée dit qui l'a portée de nouveau.

Limites

  • Le hub vérifie que le run nommé pouvait porter la ligne (Completed, même connecteur, après la lettre), pas qu'il l'a écrite.
  • Chaque nuit qui relit la ligne ajoute une lettre morte : on les ferme une par une.
  • Données synthétiques.
