Un montant illisible n'entre pas : la facture attend, corrigée à la source.

Un export de factures fournisseurs porte deux montants mal saisis et une facture de test. Au lieu d'écrire des factures sans montant, le hub les met de côté avec la ligne telle qu'elle a été lue. On écarte la facture de test, on corrige à la source, et chaque lettre est fermée par la lecture qui a apporté la bonne ligne.

L'export du jour 1 : 38 factures écrites, 3 mises de côté

Le connecteur CSV déclare on-error: dlq sur le montant. FA-2025-0013 porte 1.250.00 et FA-2025-0027 porte 87.5O : la lecture du montant échoue, la facture part en lettre morte au lieu d'être écrite sans montant. La facture de test n'a pas de fournisseur : validate-row la refuse.

    41 = 38 + 3

  2. 2
    on-error: dlq

    Par colonne ; par défaut, la case serait écrite vide.

Ce que prouve cette étape

Une valeur illisible n'est pas écrite vide : la ligne est mise de côté, et lu = écrit + écarté.

manifests/10-invoices.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-invoices-b  connector_type: csv-file  scopes: [invoices-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/invoices-dead-letters/b/invoices.csv  parser:    has_header: true  after_process: none  mapping:    on-error:      fields: { amount_eur: dlq }   # an unreadable amount: the invoice goes to the dead letters    row:      - validate-row: { required: [invoice_no, supplier_id] }    cell:      - parse-date: { column: invoice_date, formats: ["yyyy-MM-dd"] }      - parse-number: { column: amount_eur, decimal-separator: "." }

Chaque lettre dit pourquoi, et garde la ligne lue

lm dlq list donne trois lettres : deux MappingFailed sur amount_eur, une ValidationFailed sur supplier_id. lm dlq get montre FA-2025-0013 avec son montant tel qu'il est arrivé, 1.250.00. La facture n'est pas dans la table.

Limites

  • on-error s'applique aux connecteurs CSV ; dlq est refusé à côté de split-row.
  • Le hub vérifie que la lecture nommée a pu porter la ligne (même connecteur, terminée, postérieure), pas qu'elle l'a écrite.
  • Factures synthétiques.
