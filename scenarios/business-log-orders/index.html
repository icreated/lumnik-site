Le log d'hier, lu comme une source : quelles commandes les erreurs ont touchées.

Des clients appellent : leur commande « n'est jamais passée ». Le serveur écrit un log texte, un fichier par jour. Le hub le lit ligne par ligne, garde les avertissements et les erreurs, en tire la commande, et la relie au client et au statut qu'il connaît déjà. Un log métier, pas un outil de supervision.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-app-log-b  connector_type: csv-file  scopes: [support-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/business-log-orders/b/app.log  parser:    lines: true                          # one line = one row, in a column named `line`  after_process: none  mapping:    dataset:      # Runs before the cells exist: it reads the raw line. Keeps WARN and ERROR; INFO and stack traces are skipped.      - filter-where: { column: line, regex: "^\\S+ \\S+ (WARN|ERROR) .*" }    cell:      - regex-extract:          column: line          pattern: "^(\\S+ \\S+) (\\w+)\\s+\\[([^\\]]+)\\] (\\S+) - (.*)$"          groups: { 1: logged_at, 2: level, 3: server, 4: logger, 5: message }      - regex-extract: { column: message, pattern: ".*\\b(CMD-\\d+)\\b.*", groups: { 1: order_no } }      - parse-date: { column: logged_at, formats: ["yyyy-MM-dd HH:mm:ss,SSS"], zone: Europe/Paris }      - truncate: { column: message, length: 120 }

Le log d'hier, une ligne par rang

parser: lines: true lit chaque ligne entière, sans séparateur ni guillemets. filter-where garde WARN et ERROR en lisant la ligne brute, car il passe avant les cellules. Les INFO, les lignes de stack trace et une ligne qui ouvre un guillemet sans le fermer sont écartées et comptées. regex-extract tire l'heure, le niveau, le serveur, le message et la commande ; parse-date lit les millisecondes à l'heure de Paris.

Ce que prouve cette étape

La réponse du support vient du log et de l'ERP réunis, sans plateforme de logs.

Limites

  • Un log métier, pas un outil de supervision : un fichier par jour, relu en entier ; ni suivi en continu, ni rétention.
  • Une stack trace n'est pas rattachée à son erreur : ses lignes sont écartées et comptées.
  • Log et commandes synthétiques.
