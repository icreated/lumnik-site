Le SaaS derrière OAuth2 : des jetons de 30 secondes, un run de 40, aucune page perdue.

L'ERP ne bouge plus, mais une partie des commandes arrive par un SaaS récent. Ce SaaS ne prend plus de jeton fixe : il donne un identifiant client et un secret, et veut un jeton de courte durée à chaque appel. lumnik demande le jeton, le renouvelle avant qu'il expire, encaisse une rotation de clés en plein run, et dit pourquoi quand le secret est révoqué, sans jamais le montrer.

Un secret stocké, un manifeste qui le nomme, une pré-vérification

Le secret client devient un lm secret ; le manifeste ne fait que le nommer avec client_secret_env. lm source rest test demande un jeton au serveur d'autorisation et lit la première page, avant tout run.

    token_url, client_id, client_secret_env.

  2. 2

200 commandes en 40 secondes, avec des jetons de 30

Le SaaS sert 8 pages de 25 commandes, 5 secondes chacune ; ses jetons vivent 30 secondes. lumnik garde le jeton entre les pages et en demande un nouveau un peu avant son expiration : aucune page n'est refusée.

  1. 1
    8 pages

    200 commandes lues, 200 écrites.

  2. 2
    Aucun 401

    Le jeton est renouvelé avant la fin.

Un refus, un nouveau jeton, la même page relue

Après la page 2, le SaaS révoque tous ses jetons, comme lors d'une rotation de clés. La page 3 est refusée une fois ; lumnik demande un nouveau jeton et relit la même page. Le run se termine sans perte.

  1. 1
    Un seul 401

    Puis un jeton neuf, une seule fois.

  2. 2
    Même page

    La requête d'origine, signée à nouveau.

invalid_client : dit à la pré-vérification et sur le run

Le secret client est changé côté SaaS. lm source rest test et le run disent la même phrase : le serveur d'autorisation refuse, avec son code d'erreur standard. Ni le secret, ni le jeton, ni la description libre du serveur n'apparaissent dans ce que lumnik affiche.

  1. 1
    invalid_client

    Le code du serveur, rien d'autre.

  2. 2
    Aucun secret

    Ni dans les sorties, ni dans les preuves.

Ce que prouve cette étape

Un secret révoqué se voit avant le run, et ne fuit nulle part.

Limites

  • Flux client credentials uniquement : ni connexion par navigateur, ni jeton de rafraîchissement, ni mTLS.
  • Un jeton de moins de 8 caractères est refusé : trop court pour être distingué des données que la source renvoie.
  • SaaS simulé, commandes synthétiques.
