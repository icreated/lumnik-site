SENAITE: la boîte de Fleming qui attend sa vérification

Objectif Être prévenu quand un résultat du LIMS SENAITE dépasse sa limite, puis quand il reste sans vérification.

Un vrai SENAITE 2.6, cinq équipes de recherche, 120 boîtes de culture lues par son API JSON.

  • body-link: les 120 analyses en cinq pages, le total vérifié;
  • 2400 colonies sur la boîte de Fleming: une décision, clé analysisrequest-24;
  • non vérifiée: la boîte devient dormante, une seconde alerte.

120 boîtes de culture, cinq équipes

L'image officielle de SENAITE 2.6, un mot de passe jetable. Le runner la remplit par son API JSON: Fleming, Pasteur, Curie, Franklin et Mendel envoient 24 boîtes chacun. 119 sont comptées et vérifiées; la dernière de Fleming est reçue, pas encore comptée.

  • count: le nombre d'analyses de la liste
  • next: l'URL de la page suivante, écrite par SENAITE
  1. 1
    Deux défauts de SENAITE contournés

    Créer un service d'analyse par l'API répond par une erreur alors qu'il est enregistré; l'auto-vérification ne se règle que par le formulaire.

Les 120 analyses en cinq pages

Le hub suit le lien next de chaque page et lit items.

  • link_path: $.next, la page suivante
  • total_path: $.count, le total vérifié
  • complete=yes: le résultat lui-même, pas seulement le résumé du catalogue
  1. 1
    Pas de page vide

    La lecture s'arrête après b_start=100: SENAITE n'écrit plus de next.

Ce que prouve cette étape

Une ligne de pagination suffit pour lire SENAITE.

Une décision au-delà de 100 colonies

Le Process écoute la table du connecteur REST (ext.scenario_senaite_c).

  • when: result>100, la limite d'une boîte propre
  • key: sample, la décision porte le nom de l'échantillon
  1. 1
    Appliqué avant le comptage

    Un Process n'évalue pas les lignes déjà là: seules les nouvelles et celles qui changent à la source.

Ce que prouve cette étape

Une source REST déclenche une décision.

manifests/20-plate-over-limit.yaml
apiVersion: apps.lumnik.io/v1kind: Processmetadata:  name: scenario-senaite-over-limit-aspec:  scope: laboratory  on:    event: data.row.changed    table: ext.scenario_senaite_a                      # the REST connector's own table (icreated/lumnik#1816)  when:    - result>100                                       # a clean plate holds at most 100 colonies  emit:    type: decision.plate-over-limit-a    key: sample                                        # the inbox shows the sample, not the row hash (icreated/lumnik#1823)    message: "{sample} ({research_group}): {result} {unit}, a clean plate holds at most 100 — state {review_state}"

La boîte de Fleming: une décision

Ada Lovelace compte la boîte de Fleming dans SENAITE: 2400 colonies, une moisissure. Le second run relit les 120 analyses; une seule ligne a changé, elle lève la décision.

  • --wait-evaluated: attendre que le Process ait lu le run
  1. 1
    Avant la correction

    La clé de la décision était l'empreinte de la ligne: 64 caractères qu'aucun laborantin ne reconnaît.

Non vérifiée: la boîte dort

Le Workflow suit review_state, l'état que SENAITE écrit. Au deuxième balayage, la boîte de Fleming est restée to_be_verified au-delà du seuil.

  • key: sample, une analyse suivie par échantillon
  • dormancy.after: 1m pour le rejeu; un laboratoire écrirait 2d
  • verified: terminal, une boîte vérifiée ne dort jamais
  1. 1
    Le balayage

    Il passe toutes les 15 minutes: le rejeu complet dure jusqu'à 35 minutes.

Ce que prouve cette étape

Un résultat oublié devient une alerte, sans relance à la main.

Limites

  • La dormance compte depuis la première fois que lumnik voit l'état, pas depuis la date de soumission dans SENAITE.
  • Le {since} du message est une date UTC: une boîte vue à 00:09 heure de Paris le 5 novembre affiche «since 2026-11-04».
  • body-link n'envoie pas de taille: les 25 par page de SENAITE gouvernent le run. Mettre limit= dans path: pour la changer.
  • Équipes et boîtes fictives, clin d'œil à leurs homonymes; données synthétiques.

Laboratoire · microbiologie

Les résultats sont dans SENAITE.

Il faut être prévenu d'un résultat hors limite.

SENAITE 2.6, 120 boîtes de culture

Le problème

La boîte de Fleming compte 2400 colonies.

  • Une boîte propre en compte au plus 100.
  • Le résultat attend sa vérification.

Ce qui n'est pas modifié

SENAITE reste tel quel.

  • Son API JSON, telle qu'elle est.
  • Aucun module, aucun export.

Ce qu'il a fallu écrire

when: [ result>100 ]
key: sample

Un Process sur la table REST.

  • Une décision quand la boîte dépasse 100.
  • Un Workflow quand elle dort non vérifiée.

Ce qui a été corrigé

Deux trous trouvés, deux corrections.

  • Une source REST alimente un Process (#1816).
  • La décision porte le nom de l'échantillon (#1823).
