Drupal parle JSON:API: on nomme le standard, une ligne lit tout le site.

Objectif Lire tous les articles d'un site Drupal par son module JSON:API, sans écrire la pagination.

Drupal 11 expose ses contenus par JSON:API, un module de son cœur. La page suivante est dans links.next, que Drupal écrit comme un objet {"href": …}. lumnik a un preset pour ce standard:

  • pagination: { kind: json-api }, et les 5 pages sont suivies;
  • 45 articles lus, 45 écrits dans le hub.

Un vrai Drupal 11, JSON:API activé

Drupal 11.4 sur SQLite, installé par drush. 45 articles. Le module JSON:API, dans le cœur de Drupal, répond:

  • data: les articles de la page
  • links.next: la page suivante, écrite comme un objet {"href": …}
  • page[limit], page[offset]: la pagination du standard
  1. 1
    Le lien objet

    La spécification JSON:API accepte un lien en chaîne ou en objet avec href; Drupal écrit l'objet.

Ce que prouve cette étape

Drupal pagine selon le standard JSON:API.

manifests/lab-docker-compose.yml

Une ligne: pagination: { kind: json-api }

Un connecteur rest-generic.

  • pagination: json-api: suit links.next, lit data
  • fields[node--article]: seuls les champs utiles sont demandés
  • unique_key: l'identifiant JSON:API de l'article

Limites

  • Le hub lit ce que l'API publie: un contenu non publié n'est pas lu sans compte.
  • Drupal ne publie pas de total par défaut: aucun témoin ne compare le compte lu au compte réel.
  • Avant icreated/lumnik#1638, le preset json-api échouait sur un lien objet; le rejeu de cette page tourne sur un hub corrigé.
  • Site Drupal de démonstration, articles synthétiques.

Le problème

Chaque API pagine à sa façon.

  • Écrire la pagination à la main, c'est une source d'erreurs.
  • Drupal suit un standard: JSON:API.

Ce qui n'est pas modifié

Drupal reste tel quel.

  • Le module JSON:API de son cœur, activé.
  • Aucun module ajouté, aucun code.

Ce qu'il a fallu écrire

pagination: { kind: json-api }

On nomme le standard.

Un connecteur de 23 lignes.

Le rouge

Le rejeu a trouvé un défaut.

  • Drupal écrit le lien suivant comme un objet.
  • Le preset ne le suivait pas: corrigé (icreated/lumnik#1638).

Le vert

45 articles, 5 pages.

  • Chaque page suivante lue dans links.next.
  • Chaque article rangé sous son identifiant Drupal.

La limite

Le hub lit ce que l'API publie.

  • Un contenu non publié n'est pas lu sans compte.
  • Drupal ne publie pas de total: aucun témoin du compte.
