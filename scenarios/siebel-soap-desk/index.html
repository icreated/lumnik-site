Le guichet SOAP du CRM : chaque service lu à sa façon, rien de lu deux fois.

Un CRM des années 2000 expose ses données par des services web SOAP sur mesure : les actions d'une demande en un appel, les opportunités d'un client page par page sur un numéro de page. Le mot de passe voyage dans l'enveloppe. lumnik lit chacun comme il se lit, dit le Fault du service tel quel, et n'envoie jamais deux fois la même requête.

L'enveloppe telle qu'elle part, le mot de passe en secret

Deux connecteurs REST au format SOAP sur le même guichet. L'en-tête porte le compte de service comme le CRM l'attend ; le mot de passe est un secret du hub, résolu à l'envoi. Le pré-vol envoie la vraie requête et lit la réponse.

  1. 1
    SOAPAction

    Chaque service est nommé comme le CRM l'expose.

  2. 2
    {{page}}

    Le numéro de page, à partir de 1, là où le service l'attend.

Les actions d'une demande, en une seule requête

Le service rend toutes les actions de la demande d'un coup. Le corps ne porte aucun numéro de page : la requête suivante serait la même, le hub n'en envoie qu'une.

  1. 1
    Lu

    Quatre actions, chacune sur sa clé.

  2. 2
    Un appel

    Le CRM n'a vu qu'une requête.

Pages 1, 2, 3, puis l'arrêt sur lastpage

Le service pagine par numéro de page et dit dans un attribut si la page est la dernière. Le hub demande 1, 2, 3 et s'arrête quand lastpage vaut true.

  1. 1
    Numéro de page

    Pas un décalage de lignes : 1, 2, 3.

  2. 2
    Arrêt

    Sur le drapeau du service, pas sur un compte.

Le Fault du service sur le run, une seule tentative

Le mot de passe du compte de service a changé côté CRM. Le run échoue avec le message du service tel quel ; il n'est pas rejoué, le CRM ne voit qu'une requête.

  1. 1
    Le message du CRM

    Avec son code, pas un « HTTP 500 ».

  2. 2
    Pas de rejeu

    Un refus ne se corrige pas en réessayant.

Deux actions nouvelles, deux qui se terminent

Le mot de passe rétabli, la nuit suivante relit la demande : deux actions ajoutées, deux passées à « Terminée ». Chaque ligne est réécrite sur sa clé.

  1. 1
    Six actions

    Les nouvelles et les modifiées.

  2. 2
    Sur la clé

    idAction, pas de doublon.

Ce que prouve cette étape

Une nuit de plus met à jour, n'empile pas.

Limites

  • Une lecture SOAP se fait en une passe, en mémoire : lm run cancel n'agit qu'à la fin de la lecture.
  • Le service est appelé pour une demande et un client écrits dans le manifeste ; un appel par demande d'une liste n'est pas couvert.
  • La marque d'un import incrémental voyage dans l'URL, pas dans le corps : un service qui filtre par période dans le corps est relu en entier.
  • CRM simulé ; données synthétiques.
