Une GMAO remplacée qui reste allumée pour quelques audits par an

Objectif Lire et archiver les trente ans d'ordres de travail d'une GMAO remplacée, puis l'éteindre et répondre encore aux audits qui citent un ordre.

Une GMAO remplacée reste allumée pour quelques lectures de conformité par an. lumnik la lit une dernière fois, archive ce qu'il a lu, puis on éteint la machine.

  • 3 600 ordres lus par le planning habituel
  • une archive S3 sous une seule empreinte
  • après l'extinction: la même ligne, les mêmes octets

Trente ans d'ordres de travail, lus par le planning

Le connecteur JDBC garde son planning habituel; le rejeu le passe à chaque minute. Le compte n'a que SELECT, son mot de passe est un secret du hub.

  • 3 600 ordres de 1995 à 2024
  • le run part du planning, pas à la main
  1. 1
    3 600 ordres

    De 1995 à 2024, sur leur numéro.

  2. 2
    Par le planning

    Le run part tout seul, pas à la main.

Un ordre par son numéro, et un numéro jamais émis

Un audit cite un ordre de travail: le hub le rend. Il cite aussi un numéro jamais émis: la réponse est «no rows».

  • WO-001234: une ligne, telle que la GMAO l'avait
  • WO-009999: aucune ligne, un non vérifié

Le run suivant dit pourquoi, la pause arrête le planning

La machine est éteinte. Au créneau suivant, le run échoue en nommant la table, le SQLSTATE et la panne.

  • host not resolved: la machine n'existe plus
  • lm connector pause arrête le planning
  • deux créneaux passent sans run
  1. 1
    host not resolved

    La machine n'existe plus sur le réseau.

  2. 2
    (paused)

    Le planning est arrêté, et la liste le dit.

Limites

  • Un connecteur dont la source est éteinte échoue à chaque créneau jusqu'à sa mise en pause; le hub ne le met pas en pause de lui-même.
  • lm source jdbc discover cite encore le message du pilote.
  • La rétention du compartiment (verrouillage d'objet) relève du stockage, pas du hub.
  • GMAO et compartiment simulés; données synthétiques.

Le problème

Trente ans d'ordres de travail retiennent la machine.

  • 3 600 ordres, de 1995 à 2024.
  • Un audit peut citer n'importe lequel.
  • Éteindre, c'est perdre la réponse.

Rien n'est migré

La GMAO est lue telle qu'elle est.

  • Un compte en lecture seule.
  • Pas de reprise de données.
  • Aucune application à développer.

Ce qu'il a fallu écrire

filename: work-orders-final.csv
mode: snapshot

Une archive, un nom, livrée une fois.

Le scénario complet tient en 3 fichiers de déclaration, 63 lignes.

La preuve

Une seule empreinte.

  • L'instantané local.
  • Le reçu de l'export.
  • L'objet relu dans le compartiment.

SHA-256 6cfa21ba…92fc2, rejeu du 3 novembre 2026.

La machine éteinte

Le run suivant dit pourquoi il échoue.

Une pause arrête le planning.

La limite

Le hub ne se met pas en pause tout seul.

  • Sans pause, chaque créneau échoue.
  • La rétention du compartiment relève du stockage.
  • Le message du pilote reste visible dans discover.
