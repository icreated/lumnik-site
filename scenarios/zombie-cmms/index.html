Le système zombie : trente ans d'ordres de travail, la machine éteinte, le hub répond toujours.

Une GMAO remplacée depuis des années reste allumée pour quelques lectures de conformité par an : la licence, la machine, et la seule personne qui sait la redémarrer. lumnik la lit une dernière fois, archive ce qu'il a lu sous une seule empreinte, puis on éteint la machine. Le run suivant dit pourquoi il échoue, la pause arrête le planning, et le hub rend les mêmes octets qu'avant.

Trente ans d'ordres de travail, lus par le planning

Le connecteur JDBC de la GMAO garde son planning habituel ; le rejeu le passe à chaque minute pour voir la suite sans attendre la nuit. Le compte de lecture n'a que SELECT, son mot de passe est un secret du hub.

  1. 1
    3 600 ordres

    De 1995 à 2024, sur leur numéro.

  2. 2
    Par le planning

    Le run part tout seul, pas à la main.

Un ordre par son numéro, et un numéro jamais émis

Une demande de conformité cite un ordre de travail : le hub le rend. Elle cite aussi un numéro que la GMAO n'a jamais émis : la réponse est « no rows », pas une erreur.

  1. 1
    WO-001234

    Une ligne, telle que la GMAO l'avait.

  2. 2
    WO-009999

    Aucune ligne : un non vérifié.

Ce que prouve cette étape

Le hub répond aux lectures de conformité à la place de la GMAO.

Une empreinte pour l'instantané, le reçu et l'objet stocké

lm entity export écrit l'instantané local et donne son SHA-256. L'export S3 dépose le même fichier dans le compartiment d'archive, sous un nom fixe ; son reçu porte la même empreinte, et l'objet relu dans le compartiment aussi.

  1. 1
    Même SHA-256

    Instantané, reçu et objet stocké.

  2. 2
    Un nom fixe

    L'archive finale est livrée une fois.

Ce que prouve cette étape

Ce qui est archivé est exactement ce que le hub a lu.

Le run suivant dit pourquoi, la pause arrête le planning

La machine est éteinte. Au créneau suivant, le run échoue avec une phrase qui nomme la table, le SQLSTATE et le genre de panne, sans le texte du pool ni celui du pilote. lm connector pause arrête le planning, lm connector list le dit, et les deux créneaux suivants passent sans run.

  1. 1
    host not resolved

    La machine n'existe plus sur le réseau.

  2. 2
    (paused)

    Le planning est arrêté, et la liste le dit.

La même ligne, la même empreinte, l'archive intacte

Sans la GMAO, le hub rend la même ligne pour WO-001234 et le même SHA-256 pour l'instantané. Un second envoi de l'archive est refusé : le fichier livré n'est jamais remplacé.

  1. 1
    Mêmes octets

    L'empreinte d'avant l'extinction.

  2. 2
    Jamais remplacée

    Le compartiment garde la première livraison.

Limites

  • Un connecteur dont la source est éteinte échoue à chaque créneau jusqu'à sa mise en pause ; le hub ne le met pas en pause de lui-même.
  • lm source jdbc discover cite encore le message du pilote.
  • La rétention du compartiment (verrouillage d'objet) relève du stockage, pas du hub.
  • GMAO et compartiment simulés ; données synthétiques.
