La balance âgée prisonnière d'un fichier d'impression

Objectif Transformer un fichier d'impression comptable paginé en créances par facture, en conservant le bon client malgré les changements de page et en écartant les en-têtes et les totaux.

La compta imprime sa balance âgée dans un fichier spool.

  • un en-tête par page;
  • un client, ses factures en dessous, un total;
  • les factures d'un client continuent parfois page suivante.

Le recouvrement veut chaque facture avec son client.

Un état imprimé, sans sa mise en page

Le connecteur lit l'état tel qu'imprimé.

  • lines: true: une ligne de l'état = une ligne lue, colonnes à position fixe
  • filter-where: ne garde que les lignes client (411…) et les factures (FA…)
  • regex-extract: découpe pièce, dates, solde et retard
  • parse-date, parse-number: 28/07/2026 devient une date, 1 840,20 un nombre
  1. 1
    10 lignes

    Mise en page et totaux, comptés dans SKIPPED.

  2. 2
    Pourquoi ce filtre

    En-têtes de page et totaux ne sont pas des créances.

Ce que prouve cette étape

Un état fait pour l'imprimante se lit comme une table.

manifests/10-aged-balance.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-agedbal-b  connector_type: csv-file  scopes: [credit-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/aged-balance-print/b/*.lst   # the accounting system's print spool  parser:    lines: true                    # a printed report: one line per row, columns by position  after_process: none  mapping:    dataset:      - filter-where: { column: line, regex: "411.*| {10}FA.*" }   # a client's header, an invoice; page headers and totals are not    cell:      - regex-extract: { column: line, pattern: "^(411\\S*)\\s+(.+?)\\s*$", groups: { 1: client_code, 2: client_name } }      - regex-extract:             # an invoice: piece, invoice date, due date, balance, days late          column: line          pattern: "^ {10}(FA\\S+)\\s+(\\d{2}/\\d{2}/\\d{4}) (\\d{2}/\\d{2}/\\d{4})\\s+([\\d ]+,\\d{2})\\s+(\\d+)\\s*$"          groups: { 1: piece, 2: invoice_date, 3: due_date, 4: balance, 5: days_late }      - parse-date: { column: invoice_date, formats: ["dd/MM/yyyy"] }      - parse-date: { column: due_date, formats: ["dd/MM/yyyy"] }      - parse-number: { column: balance }      - parse-number: { column: days_late, integer: true }      - fill-down: { columns: [client_code, client_name] }   # the client, on the invoices under its header — across a page break

Limites

  • Une ligne écartée par filter-where ne reporte rien: le filtre doit garder les lignes client.
  • L'entité a pour clé la ligne imprimée: une facture réimprimée à l'identique est la même ligne.
  • Fichier synthétique, clients et factures fictifs.

Recouvrement · état imprimé

À quel client est cette facture?

La balance âgée existe, mais seulement imprimée.

Un fichier spool: en-têtes de page, clients, factures, totaux.

Fichier synthétique, clients fictifs

Le problème

Le saut de page coupe un client en deux.

  • Page 1: le client et deux factures.
  • Page 2: trois factures, sans le client.
  • Le recouvrement ressaisit l'état.

Rien n'est modifié

L'état reste tel qu'imprimé.

  • lumnik lit chaque ligne.
  • Il écarte mise en page et totaux.
  • Il reporte le client sur ses factures.

Ce qu'il a fallu écrire

- fill-down:
    columns: [client_code, client_name]

Le client descend sur ses factures.

Le scénario complet tient en 2 fichiers de déclaration, 46 lignes.

Le résultat

12 factures, chacune avec son client.

  • 411ANSE: 5 factures sur 2 pages, 8 957,30.
  • Les totaux imprimés retrouvés.
  • FA26-0644: 85 jours de retard.

La limite

Le filtre doit garder les lignes client.

  • Une ligne écartée ne reporte rien.
  • Une facture réimprimée à l'identique est la même ligne.
