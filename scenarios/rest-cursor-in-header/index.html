Le transporteur lit son curseur dans un en-tête: placé ailleurs, le run échoue au lieu de mentir.

Objectif Lire tous les événements de suivi d'un transporteur dont l'API attend le curseur de page dans un en-tête de requête.

L'API de suivi d'un transporteur pagine par curseur. Elle le lit dans l'en-tête X-Next-Cursor, et nulle part ailleurs:

  • envoyé en paramètre d'URL, le défaut, le curseur n'arrive pas: l'API renvoie la première page et dit qu'il y en a d'autres; le run échoue et dit pourquoi;
  • une ligne, cursor_binding: header, et les 1200 événements passent, 12 pages.

1200 événements, le curseur dans un en-tête

Une API de transporteur, simulée pour le rejeu: 1200 événements de suivi, 100 par page.

  • has_more: il reste des pages
  • next_cursor: le curseur de la page suivante
  • la page suivante se demande par l'en-tête X-Next-Cursor; ailleurs, le curseur est ignoré
  1. 1
    Pourquoi simulée

    Peu d'API publiques font ainsi; le comportement est celui des API partenaires qui le font.

Curseur en paramètre d'URL: le run échoue

Le connecteur envoie le curseur en paramètre d'URL, le défaut. L'API l'ignore et renvoie la première page, avec le même curseur. lumnik refuse de s'arrêter là: le run échoue et nomme les clés à vérifier.

  1. 1
    IN 0

    Aucune page n'est écrite comme si elle était la seule.

  2. 2
    Le message

    Il nomme l'endpoint, jamais la valeur du curseur.

Transport · suivi des colis

Le transporteur publie 1200 événements de suivi.

L'import doit tous les lire, page après page.

API de transporteur simulée

Le problème

L'API attend la page suivante dans un en-tête.

  • Envoyée ailleurs, elle est ignorée.
  • L'API renvoie alors la première page.
  • Elle dit pourtant qu'il en reste.

Ce qui n'est pas modifié

L'API reste telle quelle.

  • Un jeton du transporteur, rangé par lm secret.
  • Aucun développement côté transporteur.

Ce qu'il a fallu écrire

cursor_binding: header
cursor_param: X-Next-Cursor

Dire où va le curseur.

Un connecteur de 30 lignes.

Le rouge

Curseur mal placé: le run échoue.

  • Il dit pourquoi, et quelle clé vérifier.
  • Aucune lecture partielle annoncée complète.

Le vert

1200 événements, 12 pages.

  • 300 colis, chacun avec son dernier statut.
  • Le curseur part dans l'en-tête à chaque page.

La limite

Le refus suppose que l'API répète sa page.

  • Une API qui renverrait des pages au hasard ne serait pas reconnue.
  • Le témoin du compte reste le total qu'elle publie, si elle en publie un.
