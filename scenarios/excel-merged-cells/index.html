Chaque ligne de l'export Excel retrouve sa région et son client

Objectif Lire un rapport Excel aux cellules fusionnées comme une table, une ligne par vente.

Les ventes envoient chaque mois un rapport Excel. Un groupe par client, la région et le client dans des cellules fusionnées, un sous-total sous chaque groupe. En CSV, une cellule fusionnée ne garde sa valeur que sur la première ligne.

  • les 15 sous-totaux écartés et comptés;
  • chaque ligne reçoit la région et le client de son groupe;
  • rien ne passe d'un fichier à l'autre.

Ce que prouve cette étape

Un rapport mis en forme pour l'œil se lit comme une table.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-excel-b  connector_type: csv-file  scopes: [sales-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/excel-merged-cells/b/*.csv   # one Excel sales export per month  parser:    delimiter: ";"  after_process: none  mapping:    dataset:      - filter-where: { column: Date, regex: "\\d{2}/\\d{2}/\\d{4}" }   # the sale lines: a subtotal has no date    row:      - map-columns:          rename:            Région: region            Client: client            Date: sale_date            Pièce: piece            Article: article            Quantité: quantity            Montant HT: amount    cell:      - regex-extract: { column: sale_date, pattern: "^\\d{2}/(\\d{2})/\\d{4}$", groups: { 1: month } }      - parse-date: { column: sale_date, formats: ["dd/MM/yyyy"] }      - parse-number: { column: quantity, integer: true }      - parse-number: { column: amount }      - fill-down: { columns: [region, client] }   # a merged cell: written on its group's first row only

Limites

  • fill-down suit l'ordre du fichier: sort-by à côté est refusé.
  • Une ligne écartée par filter-where ne reporte rien: la première ligne d'un groupe ne doit pas être filtrée.
  • Fichiers synthétiques, clients fictifs.

Ventes · Excel

Le rapport des ventes est un Excel.

Fait pour l'œil, pas pour une table.

Deux mois, 1097 lignes de vente

Le problème

Les cellules fusionnées se vident.

  • En CSV, seule la première ligne garde le client.
  • Les suivantes sont vides.

Ce qui n'est pas modifié

Le rapport reste tel quel.

  • Le même export, chaque mois.
  • Rien n'est retouché à la main.

Le piège

Un groupe coupé en deux.

  • Le hub lit par morceaux de 500 lignes.
  • Un client est à cheval sur deux.

Ce qu'il a fallu écrire

fill-down: { columns: [region, client] }

Une ligne.

  • La valeur descend sur son groupe.
  • Elle passe d'un morceau à l'autre.
  • Deux manifestes, 50 lignes.

La preuve

13 603,90, le sous-total retrouvé.

  • 84 lignes, toutes au bon client.
  • Les 15 sous-totaux comptés à part.

La limite

L'ordre du fichier compte.

  • fill-down suit les lignes dans l'ordre.
  • Un tri à côté est refusé.
