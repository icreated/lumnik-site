Odoo lu dans son PostgreSQL: le nom du produit est un JSON

Objectif Lire les produits d'un vrai Odoo 18 directement dans sa base, voir ce qui arrive vraiment, et obtenir le nom français de chaque produit.

Depuis Odoo 16, un champ traduit est un JSON par ligne, une clé par langue. Chaque rapport écrit sur l'ancienne colonne texte a cassé. Un intégrateur qui lit la base d'Odoo le rencontre dès product_template.name.

  • lu tel quel: le nom arrive en texte JSON
  • le nom français demandé: Ask s'abstient
  • une vue du DBA, dans un schéma à part: quatre noms français

Le nom arrive en texte JSON

Un vrai Odoo 18 tourne en Docker. Les produits sont créés par son API XML-RPC. Le connecteur lit product_template avec un login en lecture seule.

  • rename: id est une colonne du hub, il arrive sous product_tmpl_id
  • target: la table du hub porte son propre nom
  • name: une colonne jsonb arrive en TEXT, le JSON tel quel
  1. 1
    Ce qui arrive

    Ask liste les quatre noms en JSON.

  2. 2
    Refus

    Le nom français demandé: Ask s'abstient au lieu d'inventer.

Une vue dans un schéma à part

Le DBA écrit une vue dans le schéma lumnik_read et l'accorde au login de lecture. Les tables d'Odoo ne changent pas.

  • name->>'fr_FR': le nom français
  • COALESCE vers en_US: le repli d'Odoo lui-même
  • un second connecteur lit la vue
  1. 1
    Odoo intact

    Aucune table d'Odoo n'est modifiée.

  2. 2
    Lecture seule

    Le login ne lit que product_template et la vue.

Limites

  • La vue est écrite dans la base du client: lumnik ne sait pas encore choisir une clé dans une colonne jsonb (icreated/lumnik#2120).
  • Odoo Online n'ouvre pas sa base: ce chemin vaut pour un Odoo installé sur site ou chez un partenaire.
  • Les hooks ne tournent pas sur jdbc-generic: rien ne transforme la colonne à l'entrée.
  • Quatre produits synthétiques.

Ce scénario demande lumnik Pro.
