Odoo lu dans son PostgreSQL: le nom du produit est un JSON

Objectif Lire les produits d'un vrai Odoo 18 directement dans sa base et obtenir le nom français de chaque produit, sans rien écrire dans Odoo.

Depuis Odoo 16, un champ traduit est un JSON par ligne, une clé par langue. Chaque rapport écrit sur l'ancienne colonne texte a cassé. Un intégrateur qui lit la base d'Odoo le rencontre dès product_template.name.

  • le nom arrive en texte JSON, toutes les langues gardées
  • promote lit la clé fr_FR dans une colonne à part, avec repli sur en_US
  • la question en langage naturel donne les quatre noms français

Le nom arrive en JSON, sa clé française en colonne

Un vrai Odoo 18 tourne en Docker. Les produits sont créés par son API XML-RPC. Le connecteur lit product_template avec un login en lecture seule.

  • rename: id est une colonne du hub, il arrive sous product_tmpl_id
  • name: une colonne jsonb arrive en TEXT, le JSON tel quel
  • promote: la clé $.fr_FR devient la colonne name_fr
  • fallback: $.en_US pour un produit jamais traduit, la règle d'Odoo
  1. 1
    Odoo intact

    Rien n'est écrit dans la base d'Odoo.

  2. 2
    Toutes les langues

    La colonne name garde le JSON entier.

Ce que prouve cette étape

La langue se déclare à l'entrée, dans le manifeste.

manifests/10-product-template.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-odoo-products-a  connector_type: jdbc-generic  scopes: [odoo-a]spec:  connection:    url: jdbc:postgresql://host.docker.internal:55433/scen    user: lumnik_reader    password_env: SCENARIO_ODOO_A_DB  source:    tables:      - name: product_template        schema: public        mode: full        pk_columns: [id]        rename: { id: product_tmpl_id }   # id is one of the hub's own columns        target: odoo_product_template_a   # connector.t_odoo_product_template_a, its own hub table        promote:          - name: name_fr                 # the French name, in a column of its own            column: name                  # Odoo 16+: {"en_US": …, "fr_FR": …}            path: $.fr_FR            fallback: $.en_US             # never translated: the English name, as Odoo shows it            type: text

Le nom français de chaque produit

La question est posée telle qu'un vendeur la tape. Ask lit la colonne name_fr.

  • Chaise de bureau, Bureau assis-debout, Lampe de bureau
  • CABLE-04, jamais traduit: USB-C cable, comme Odoo l'affiche
  1. 1
    Repli

    Un produit sans traduction garde son nom anglais.

  2. 2
    SQL

    La réponse montre sa requête.

Limites

  • La langue est écrite dans le manifeste: le hub ne la choisit jamais d'après le lecteur.
  • Avant icreated/lumnik#2122, la question s'abstenait et le chemin était une vue dans la base d'Odoo, écrite par le DBA (data/view.sql).
  • Odoo Online n'ouvre pas sa base: il se lit par son API JSON-2 (odoo-json2-partners).
  • Quatre produits synthétiques.

Ce scénario demande lumnik Pro.
