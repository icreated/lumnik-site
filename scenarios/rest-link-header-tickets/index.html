Un ticket fermé reste ouvert dans le hub, tant qu'on ne lit que les ouverts.

Objectif Suivre les tickets ouverts d'une forge Gitea, paginée par l'en-tête Link, sans garder ouvert un ticket que le support a fermé.

Le support suit ses tickets clients dans Gitea. Son API pagine comme GitHub: la page suivante est dans l'en-tête Link. lumnik suit l'en-tête, page après page:

  • lire state=open laisse ouverts, dans le hub, les tickets fermés depuis: ils sortent du filtre de l'API;
  • lire tous les états, par ce qui a changé depuis le dernier run, garde le hub juste: 57 ouverts, comme Gitea.

Gitea: 95 tickets, la page suivante dans l'en-tête

Une vraie forge Gitea 1.22. Ses tickets sont ceux du support: 3 clients fictifs, un label bloquant, 72 ouverts.

  • Link: la page suivante, et la dernière
  • X-Total-Count: le nombre de tickets du filtre
  • le corps n'est que la liste: aucune pagination dedans
  1. 1
    ROOT_URL

    Gitea écrit ses liens avec l'adresse que le hub joint.

Ce que prouve cette étape

La pagination est dans les en-têtes.

72 tickets, 3 pages, par l'en-tête Link

Un connecteur rest-generic.

  • auth: un jeton Gitea en lecture seule, rangé par lm secret
  • pagination: link-header: suit rel="next" jusqu'à la dernière page
  • response_path: $: le corps est la liste
  • client, blocking: lus dans les labels du ticket

Ce que prouve cette étape

L'en-tête Link est suivi jusqu'au bout.

Tous les états, par ce qui a changé

Le même connecteur, autrement déclaré.

  • state=all: les fermés sont lus aussi
  • state: une colonne; fermé se lit fermé
  • incremental: since reçoit le plus récent updated_at du run précédent

Limites

  • Un ticket supprimé dans Gitea n'est plus renvoyé: sa ligne reste dans le hub, avec son dernier état.
  • La marge de relecture vaut une minute plus la durée du run: un ticket changé juste avant est relu, jamais perdu.
  • Ce rejeu ne déclare pas X-Total-Count comme témoin du compte; total_header le permet depuis icreated/lumnik#1632, voir le scénario WordPress.
  • Forge Gitea de démonstration, tickets synthétiques.

Forge Gitea de démonstration

Le problème

Un filtre ne voit pas ce qui en sort.

  • L'import ne lit que les tickets ouverts.
  • Un ticket fermé n'est plus renvoyé.
  • Sa ligne reste ouverte.

Ce qui n'est pas modifié

Gitea reste tel quel.

  • Un jeton en lecture seule.
  • La pagination de Gitea, suivie par l'en-tête Link.

Ce qu'il a fallu écrire

path: …/issues?state=all
pagination: { kind: link-header }
incremental: { mode: watermark, param: since }

Tous les états, seulement ce qui a changé.

Le rouge

Gitea: 60 ouverts. Le hub: 72.

  • Le run est vert.
  • 12 tickets fermés restent ouverts.

Le vert

Gitea: 57 ouverts. Le hub: 57.

  • Le lendemain, 15 tickets relus, pas 95.
  • L'état est une colonne: fermé se lit fermé.

La limite

Un ticket supprimé n'est pas vu.

  • Gitea ne renvoie plus un ticket supprimé.
  • La ligne reste dans le hub, avec son dernier état.
