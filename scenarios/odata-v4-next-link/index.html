OData v4 paginé par le serveur: lumnik suit @odata.nextLink

Objectif Lire les 120 clients d'un service OData v4 paginé par le serveur, comme Business Central, en pages de 20 demandées par Prefer, sans en perdre un.

Business Central pagine ses réponses OData côté serveur, et un client demande des pages plus petites avec Prefer: odata.maxpagesize. La page suivante n'est pas un paramètre calculé: c'est @odata.nextLink, une URL que le serveur renvoie.

  • un vrai service ASP.NET Core OData v4
  • le preset odata-v4, le total $count comme témoin
  • six pages de 20, 120 clients
  • lumnik Open
  • ERP
  • API
  • Microsoft
  • Connector

Six pages de 20, 120 clients

Le service ASP.NET Core OData pagine à 50. Le connecteur demande 20 par page et suit les liens du serveur.

  • kind: odata-v4, où sont les lignes, le lien suivant et le total
  • $count=true: le total que le run vérifie
  • Prefer: odata.maxpagesize=20, déclaré une fois, envoyé à chaque page
  1. 1
    Compté chez le serveur

    Son journal montre six GET, de $skip 0 à 100.

  2. 2
    Compté chez lumnik

    Le run dit IN 120, OUT 120.

Ce que prouve cette étape

Le serveur décide des pages, lumnik suit le lien qu'il rend.

manifests/10-customers.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-odata-customers-a  connector_type: rest-generic  scopes: [finance-a]spec:  base_url: http://host.docker.internal:18073  headers:    # Business Central pages at 20,000 by default; a client asks for smaller pages, as Microsoft documents.    - { name: Prefer, value: odata.maxpagesize=20 }  endpoints:    - id: customers      method: GET      path: /odata/Customers?$count=true    # $count: the total the run checks itself against      pagination: { kind: odata-v4 }        # @odata.nextLink, value, @odata.count      target:        kind: hybrid        table: connector.scenario_odata_customers_a        unique_key: $.Id        promote:          - { name: customer_no, path: $.No, type: text }          - { name: name, path: $.Name, type: text }          - { name: city, path: $.City, type: text }          - { name: balance, path: $.Balance, type: decimal }

Limites

  • Ce n'est pas Business Central: c'est le framework OData publié par Microsoft, qui pagine de la même façon. L'authentification OAuth2 de Business Central n'est pas montrée ici.
  • Un serveur peut ignorer Prefer: la taille de page est alors la sienne, et le run suit toujours le lien.
  • 120 clients synthétiques.
